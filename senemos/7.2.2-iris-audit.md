# Linux 7.2.2 Nabu Iris audit

## Decision

Keep the current Linux 7.2.2 Iris overlay as the implementation base.  It is
newer and broader than the Linux 6.17 port: the SM8150/VPU5 platform data,
Venus coordination, firmware boot gate, cached capture buffers and 10-bit P010
decode are retained, while the 7.2.2 series also carries current V4L2 API
adaptation and additional VP9/P010 fixes.

Do not replay the older Iris driver files wholesale.  Doing so would replace
the current media API adaptation and lose fixes made after the original port.

## Feature comparison

| Capability | Linux 6.17 port | Linux 7.2.2-test result |
|---|---|---|
| SM8150 Iris/VPU5 platform data | Present | Retained and adapted to 7.2.2 |
| Venus/firmware coordination | Present | Retained |
| Firmware boot opt-in gate | Present | Retained (`allow_fw_boot`) |
| Cached capture buffers | Present | Retained |
| 10-bit decode/P010 | Present | Retained, with newer P010 hardening |
| VP9 decode | Initial support | Newer hidden-superframe and legacy-output fixes retained |
| Current V4L2/media API | Older kernel API | Adapted for Linux 7.2.2 |
| Runtime power collapse on VPU5 | Unsupported | Runtime PM remains forbidden |
| System suspend on VPU5 | Could call unsupported prepare-PC path | Guarded; Iris remains powered across s2idle |

## Validation gates

Source and compile validation are necessary but do not prove video hardware.
The physical gate is: firmware request succeeds, both video nodes enumerate,
V4L2 compliance does not regress, an 8-bit H.264/VP9 sample decodes, a P010
sample decodes, repeated stream-on/off does not leak buffers, and a GNOME
suspend/resume cycle succeeds both idle and after decode.  Failures must retain
pstore/ftrace evidence before rebooting to the known-good kernel.
